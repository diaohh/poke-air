# 06 — Internationalization (i18n)

## Goal

- **English is the default and first shipped language.**
- **Spanish (Spain, `es-ES`)** as the second locale, evaluated for feasibility below.
- The language is a **room setting** chosen by the Host (the Host screen and all phones in the room use it).
  A per-device override on phones can come later.

Official Pokémon games have a single Spanish localization (Spain), so "Spanish from Spain" matches the
official names players know (Garchomp, Terremoto, Levitación, Piedra Activadora…).

## Where text comes from

| Text category                             | Examples                                    | Source                                                              | es-ES availability                                              |
| ----------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------- |
| **UI strings**                            | "Join room", "Ready", "Waiting for others…" | Our own i18next resources                                           | We write them (small, full control)                             |
| **Pokémon / move / ability / item names** | Garchomp, Earthquake → Terremoto            | Showdown `data/text/es/*.ts` (MIT)                                  | ✅ High (see table below)                                       |
| **Types, stats, natures**                 | Dragon → Dragón, Atk → Ataque               | Showdown `data/text/es/names.ts`                                    | ✅ Complete                                                     |
| **Battle messages**                       | "{POKEMON} used {MOVE}!"                    | Showdown `data/text/es/default.ts` + per-move/ability/item messages | ✅ Mostly (official Champions text)                             |
| **Short descriptions** (team builder)     | "Hits all adjacent Pokémon."                | Showdown `shortDesc`                                                | ❌ Not translated yet → English fallback or PokeAPI flavor text |
| **Trainer names**                         | Cynthia → Cintia                            | Our own table                                                       | We write them (~50 entries)                                     |

| Moves                               | 934              | 19                             | Move battle messages: 283 translated / 5 null                                      |

Showdown's `data/text/README.md` states names/descriptions were sourced from PokeAPI and Champions battle
messages from official game text, with a documented grammar for placeholders (`[POKEMON]`, modifiers
like `{TRAINER:definite:capitalize}`).

⚠️ These translated tables are in the **GitHub repo** but **not in the npm release 0.11.11** (the
package ships `dist/data/text/*.js` in English only). `packages/data` must fetch them from a **pinned
commit** of the repo at build time.

## Feasibility verdict

**High.** Showdown already provides official Spanish names and most battle messages under MIT, which
covers ~90% of what a player reads during a battle. The gaps are small and addressable:

1. Missing battle messages (~80) → our own override file `locales/es-ES/battle-overrides.json`.
2. Short descriptions → English fallback in v1 of es-ES; later PokeAPI flavor text or community translations.
3. Form names (e.g. "Rotom-Wash") → composed from the base name + our own form-suffix table.

## Architecture

```
packages/data (build time)
 ├─ pulls Showdown data/text/<lang> at a pinned commit
 ├─ merges with our overrides
 └─ emits per locale:  names.<locale>.json   (species/moves/abilities/items/types/natures by Showdown ID)
                      battle.<locale>.json  (message templates)
                      desc.<locale>.json    (short descriptions, with English fallback)

apps/web
 ├─ i18next + react-i18next, namespaces: ui, names, battle, desc
 ├─ locales lazy-loaded per room locale (English bundled; es-ES fetched on demand)
 └─ BattleTextFormatter: protocol event → template + params → localized string
```

Key rules:

- **Everything is keyed by Showdown IDs** (`garchomp`, `earthquake`, `levitate`). The server and the sim
  only ever speak IDs/English; **translation happens only on clients**.
- The **battle narration is generated on the Host** from protocol events, never taken as text from the
  server. This keeps the server language-agnostic and lets the room locale change between battles.
- Server errors are sent as `{ code, messageKey, params }`, never as prose.
- Team builder search matches **both** the localized and the English name (players often know both).
- Showdown text export/import (paste format) stays **English** (it's an interchange format).
- `@pkmn/view` can format battle text; spike S4 checks whether its formatter accepts
  custom text tables. If not, we write our own `BattleTextFormatter` (the template grammar is documented).

## Room locale

- `room.locale` is `en` today (`DEFAULT_LOCALE`). From Phase 4: default to the Host browser's language if supported.
- Changing it in LOBBY updates the Host and every phone live (`room:state`).
- Supported locales list: `SUPPORTED_LOCALES` in `packages/shared/src/constants.ts` (currently `['en']`;
  Phase 4 adds `'es-ES'`). Adding a language =
  adding UI resources + enabling the matching Showdown table (German, French, Italian, Japanese, Korean
  and Chinese tables also exist in Showdown).
